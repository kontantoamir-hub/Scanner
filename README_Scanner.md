# 📡 Scanner Bot — ماسح وإشارات تداول العملات الرقمية

> نظام آلي كامل يعمل على GitHub Actions بدون سيرفر وبلا تكلفة: يمسح سوق العملات الرقمية، يولّد **4 أنواع إشارات تداول** بمعايير موحّدة، يدير كل صفقة مفتوحة بإدارة احترافية ثلاثية الطبقات (Breakeven / إغلاق جزئي / Trailing / حماية من الانعكاس)، وينفّذ كل شيء في **محفظة ورقية** بمحاسبة دقيقة تُخزَّن على GitHub Gist.

**الملفات التنفيذية:** `scanner.py` (المسح + الإشارات + إدارة الصفقات) — `paper_trading.py` (المحفظة الورقية) — `test_mgmt_engine.py` (اختبارات محرك الإدارة)

## 📖 ما هذا المشروع؟

**المشكلة التي يحلّها:** معظم أدوات الإشارات تعطي التنبيه **بعد** أن تصبح الحركة واضحة للجميع — فيشتري المستخدم القمة. المشروع يعالج هذا من ثلاث جهات: مسار "إشارات مبكرة" يرصد الانضغاط والتراكم الصامت قبل الانفجار، وفلتر "الإرهاق" يعاقب الإشارة الرسمية نفسها لو ابتعد السعر عن EMA50 أكثر من 3 ATR، وخطة سعر موحّدة ترفض أي صفقة لا تحقق حدًا أدنى من العائد مقابل المخاطرة.

**فلسفة التصميم:** كل شيء يعمل داخل GitHub Actions المجاني — المسح المجدول، المراقبة، حفظ الحالة على Gist، والتنبيه على تيليجرام. لا سيرفر، لا قاعدة بيانات، لا تكلفة شهرية. والتنفيذ كله **ورقي (Paper Trading)** عبر محافظ وهمية منفصلة لكل نوع إشارة، لقياس أداء كل مسار بواقعية قبل أي قرار بأموال حقيقية.

**أهم مبدأ هندسي:** الإشارة ليست نهاية القصة بل بدايتها. بعد فتح الصفقة يتكفل محرك إدارة الصفقات (TM v1) بتحويلها تدريجيًا من "صفقة خطر" إلى "صفقة مجانية" ثم "صفقة مطاردة قمم"، مع طبقتي أمان مستقلتين تكتشفان انعكاس السوق أو انعكاس العملة وحدها وتتصرفان قبل SL الكامل.

| الملف | الدور | يعتمد على |
|---|---|---|
| `scanner.py` | المسح العميق، توليد الإشارات الأربع، خطة السعر الموحدة، إدارة الصفقات المفتوحة، حمايتا الانقلاب | مكتبات قياسية + `requests` + `paper_trading` |
| `paper_trading.py` | المحفظة الورقية: تنفيذ وهمي، محافظ فرعية، محاسبة، أرشفة، تيليجرام خاص | مكتبات قياسية + `requests` فقط |
| `test_mgmt_engine.py` | 29 اختبارًا لمحرك إدارة الصفقات (دورة حياة كاملة + دقة مالية) | `scanner.py` |
| `.github/workflows/` | جدولة التشغيل على cron + تشغيل يدوي | — |

**دورة تشغيل واحدة (Workflow Run):**

1. جلب تيكرز بورصة Binance وفلترة السيولة والحركة => أعمق 60 عملة (`SCAN_DEPTH`)
2. مسح عميق لكل عملة (شموع `SCAN_INTERVAL` الافتراضي 1h)
3. حساب `market_regime` العام (BTC + اتساع السوق + الهيكل السعري)
4. **حماية الصفقات المفتوحة**: طبقة Regime ثم حارس الانعكاس المحلي
5. توليد الإشارات الأربع بمعاييرها الموحدة => إرسال تنبيهات تيليجرام
6. المحفظة الورقية تنفّذ الإشارات => شموع مراقبة 5m تطبّق TM v1 على الصفقات
7. حفظ كل الحالة (أرصدة، صفقات، سجل مغلق، أرشيف) على Gist

## 🎯 الإشارات الأربع — معايير موحّدة

| النوع | الفلسفة | SL | TP1 | قواعد إضافية |
|---|---|---|---|---|
| **official** (رسمية) | نظام نقاط مكتمل مع تأكيد الفريم الأعلى | 1.5×ATR | 1.5R | score ≥ 1.5 + حجم + تقلب ≥ 0.08% + استقرار + ليست عرضية + بعيدة عن مقاومة + فلتر إرهاق 3 ATR |
| **early** (مبكرة) | رادار قبل الإشارة الرسمية (squeeze / تراكم / دايفرجنس / مومنتم) | 2.0×ATR | 1.5R | SL أوسع عمدًا (دقة أقل) — تحذير لا دخول مؤكد |
| **breakout** (انفجار) | انفجار انضغاط TTM Squeeze | 1.5×ATR | 1.5R | رفض عند تعارض الفريم الأعلى |
| **experimental** (تجريبية) | confluence_v1: AVWAP + Volume Profile + CVD + TTM + OI/Funding | 1.5×ATR | 1.5R | رفض تعارض الفريم الأعلى + رفض funding ≥ 0.10% + تقلب ≥ 0.10% |

### خطة السعر الموحدة `build_trade_plan()`

كل الأنواع الأربعة تمرّ على نفس دالة بناء الخطة — لا استثناءات:

- **TP1 = 1.5R** من مسافة SL (نسبة عائد/مخاطرة حقيقية، ليست TP = 1R كما كانت النسخة القديمة)
- يُقص TP1 عند **أقرب مقاومة** فعلية
- لو القص أسقط **RR تحت `MIN_RR` (1.0)** => **رفض الخطة كليًا** — لا صفقة بهامش وهمي
- فلتر موحد: **ATR% ≥ 0.08** لكل الأنواع (رفض الأسواق الميتة)

## 🛡️ إدارة الصفقات TM v1 — ثلاث طبقات

### الطبقة 0 — الإدارة المستمرة (كل دورة مراقبة على شموع 5m)

| المرحلة | الشرط | الفعل | رسالة تيليجرام |
|---|---|---|---|
| 1. Breakeven | السعر يصل **+1R** | SL => الدخول + العمولة (صفقة بلا خطر) | ⚖️ تعادل |
| 2. إغلاق جزئي | السعر يصل **TP1 (+1.5R)** | إغلاق **50%** والباقي عدّاء Runner | 💰 ربح جزئي |
| 3. Trailing | بعد TP1 | SL يتبع أعلى قمة على بعد **1R** — يصعد فقط ولا يهبط | 📈 تحديث تتبع |
| 4. TP2 | العدّاء يصل **TP1 + 1.5R** | إغلاق نهائي | 🏁 إغلاق كامل |

### الطبقة 1 — حماية انقلاب السوق العام (Regime Flip)

عندما يتحول `market_regime` إلى **trending_down** (بتحليل BTC على فريمات متعددة + اتساع السوق + الهيكل):

- **الصفقة الرابحة** (ربح ≥ +0.4%): SL => تعادل صافي فورًا
- **الصفقة الخاسرة** التي لامست **-0.5R**: إغلاق فوري `REGIME_EXIT` بدل انتظار -1R كاملًا
- ⚡ القياس عبر **أدنى قاع مسجل (`min_low`)** وليس السعر اللحظي — الارتدادات لا تخدعها
- الصفقات التي سبق نقل SL للتعادل (`be_done`) تُستثنى — خروجها عبر Trailing

### الطبقة 2 — حارس الانعكاس المحلي (Coin-Level Reversal Guard)

مستقل تمامًا عن السوق العام: عملة قد تنعكس وحدها بينما BTC ثابت. لكل صفقة عمرها > ساعتين (فحص **مرة واحدة** لكل صفقة):

**شرط التفعيل (كلاهما معًا):** تقاطع EMA7 تحت EMA14 هبوطًا خلال آخر 3 شموع مغلقة **+** إغلاقان متتاليان تحت EMA20

| حالة الصفقة عند التفعيل | الفعل |
|---|---|
| وصلت ربحًا ≥ **+0.5R** في قمتها | SL => قفل نصف أعلى ربح (`reversal_lock`) — يصعد فقط |
| خاسرة بأقل من **-0.6R** | خروج مبكر فوري `REVERSAL_EXIT` (خسارة 0.3–0.6R بدل -1R) |
| بينهما (قرب SL أو ربح هامشي) | لا فعل — SL الثابت كافٍ |

**Fail-safe:** أي فشل جلب بيانات => لا فعل إطلاقًا، والصفقة تبقى تحت حماية SL الثابت.

### سيناريو حياة صفقة كامل

```text
فتح LONG @ 100، SL @ 97 (3% مخاطرة = 1R)
─── +1R (103)      => SL => 100.3 (تعادل صافي) ✅ الصفقة لا تخسر بعد الآن
─── +1.5R (104.5)  => إغلاق 50% بربح مؤكد 💰 + عدّاء بـ Trailing 1R
─── السوق ينقلب trending_down => طبقة Regime تتخطاها (محمية أصلًا)
─── عملة تحقق EMA7/14 هابط + إغلاقين تحت EMA20
     => SL يقفل نصف ربح القمة أو الـ Trailing يخرجه بربح
النتيجة: TP1 محقق + عدّاء إما بـ TP2 أو خروج محمي — صفر خسارة ممكنة بعد +1R
```

## 💰 المحفظة الورقية (Paper Wallet)

- **محفظة رئيسية + 4 محافظ فرعية مستقلة** — واحدة لكل نوع إشارة (official / early / breakout / experimental)، كل واحدة برأس مال 400$ وهمي و8 شرائح (50$/صفقة) => تقيس أداء كل مسار إشارة بمعزل عن الآخر
- **محاسبة واقعية**: عمولة 0.2% (دخول + خروج)، الإغلاق الجزئي عند TP1 يعيد نصف رأس المال للمحفظة **فورًا** (يتاح لصفقات جديدة)، والصفقات تُغلق زمنيًا بعد 96 ساعة كشبكة أمان قصوى
- **أرشفة بلا فقدان**: السجل النشط يحتفظ بآخر 150 صفقة مغلقة، والأقدم يُرحَّل تلقائيًا لملفات أرشيف مرقمة داخل Gist مخصص، مع سلسلة Gists تنتقل تلقائيًا قبل اقتراب حد GitHub (300 ملف) — لا يُحذف أي سجل أبدًا
- **رسائل تيليجرام منفصلة**: بوت خاص بالمحفظة (`PAPER_TELEGRAM_*`) غير مشوبك ببوت تنبيهات السكانر

## 🚀 الإعداد خطوة بخطوة

### 1) رفع الملفات

ارفع `scanner.py` و`paper_trading.py` إلى جذر المستودع (استبدال للقديمين)، و`README.md` هذا كما هو. **لا ملفات أخرى مطلوبة** — كل ملفات الحالة تُدار تلقائيًا داخل Gist.

### 2) إعداد الـ Secrets (إلزامي قبل أول تشغيل)

`Settings → Secrets and variables → Actions → New repository secret`

| الاسم | إلزامي؟ | الوصف |
|---|---|---|
| `TELEGRAM_TOKEN` | ✅ | توكن بوت تيليجرام الخاص بتنبيهات السكانر (من BotFather) |
| `TELEGRAM_CHAT_ID` | ✅ | معرف المحادثة التي تستقبل تنبيهات السكانر |
| `GIST_TOKEN` | ✅ | توكن GitHub شخصي بصلاحية `gist` — يُستخدم للسكانر والمحفظة معًا |
| `GIST_ID` | ✅ | معرف Gist السكانر (سجل الصفقات والتعلّم التكيفي) |
| `PAPER_GIST_ID` | ✅ | معرف Gist المحفظة الورقية — **كان مكتوبًا في الكود سابقًا (تسريب أمني) وأصبح Secret إلزاميًا** |
| `PAPER_TELEGRAM_TOKEN` | اختياري | توكن بوت المحفظة الورقية المنفصل |
| `PAPER_TELEGRAM_CHAT_ID` | اختياري | محادثة رسائل المحفظة الورقية |

### 3) أول تشغيل وتحقق

1. `Actions → [workflow] → Run workflow` (تشغيل يدوي)
2. انتظر الاخضرار وافحص السجل (Log): يجب رؤية `Market Regime` وقوائم الإشارات
3. اختبار تيليجرام: أول إشارة تصلك تحتوي خطة سعر كاملة (دخول / SL / TP1)
4. اختبار المحفظة: رسائل المحفظة الورقية تظهر فتح صفقة وهمية لكل إشارة
5. تحقق أمني: `Settings → Secrets` يحتوي `PAPER_GIST_ID` — ولو نسيتَه سيظهر بالسجل: `PAPER_GIST_TOKEN أو PAPER_GIST_ID غير موجودين — تخطي هذه الدورة`

### 4) تحديثات مستقبلية

استبدال الملفين فقط هو كل ما يلزم لأي تحديث — الأرصدة والسجلات محفوظة على Gist ولا تتأثر أبدًا بتحديث الكود.
